# Phase notes

每个 phase 写一篇笔记到这里(`phase0.md`、`phase1.md`、……)。

**目标**:用自己的话写明白这一阶段在干什么,证明不是"代码能跑就行"。

> 这份 notes **才是每个 phase 的真正交付物**,源码只是副产品。

---

## 写作模板

````markdown
# Phase N:<概念名>

## 我写了什么

列出这一阶段实际写的文件 / 函数,一行一个。

## 用自己的话复述这个概念

不看代码、不看 pguso 例子,用 3 - 5 段话解释这一阶段的核心概念。
写不出来 = 没吃透 = 回头重做这个 phase。

## 踩坑记录

1 - 2 个让你卡住或最初理解错的点。格式:
- 我以为是 X
- 实际是 Y
- 为什么会搞错(根本原因)

## 自检题答案

回答 `LEARNING.md` 末尾"## 判断是否学懂"里和本阶段相关的题。

## 还没想清楚的问题

记下来 — 下一阶段继续找答案,或问 Claude。
````

---

## 为什么要写这个

1. **"代码能跑" ≠ "我懂了"**。手写文字会暴露知识漏洞,远比跑通代码筛得严
2. **未来的你**(以及未来的 Claude 会话)能从这里快速对齐到当前理解
3. **下一个 phase 卡住时**,回看上一篇 notes 经常能发现"哦原来上次没想清楚的就是这个"

## 检查清单

写完一篇 notes,自问:

- [ ] 不看代码能复述这一阶段在干嘛吗?
- [ ] 自检题都答对了吗(尤其 LEARNING.md 末尾那 7 问对应的几条)?
- [ ] 踩坑那段是不是真的有"具体的错误假设"?如果写"没踩什么坑",大概率是没认真做
- [ ] "还没想清楚的问题"那段空着也行,但**不要为了凑数硬编**
